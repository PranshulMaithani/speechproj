COMMANDSIMP_V2.txt -- v2 training commands for EC2 (drop + prior + fewshot)
================================================================================

Paths assume:
    repo       = ~/speech3
    data dir   = /home/ubuntu/nn/data
    runs dir   = /home/ubuntu/nn/runs
Adjust if yours differ.

Two recipes are run, both committing to dropping the 18 high-KS features:

    r6_drop_prior_fs10  = drop + prior + fewshot 0.10  (headline recipe)
    r6_no_fs            = drop + prior, no fewshot     (unsupervised version)

After both finish, collate with the existing r0..r5 results and analyze.

frames = []
for f in sorted(glob.glob('/home/ubuntu/nn/runs/*/summary*.csv')):

--------------------------------------------------------------------------------
NOTES
--------------------------------------------------------------------------------

* feat_n_words_asr is in HIGH_KS_FEATURES so --drop_high_ks_features=true
  removes it. No backfill needed (and the backfill must run on the company
  laptop anyway -- transcripts are PII-gated, never on EC2).

* prior_correction is MONOTONIC. test_best_f1 will NOT change between
  prior_correction=true and false -- the sweep finds the same max. What
  changes is test_f1@0.5 and the optimal threshold value. If you compare
  r6 vs r6_no_fs and best_f1 looks similar, that's prior_correction
  behaving correctly, NOT a no-op of feature drop.

* The win, if there is one, will show up as:
    - test_best_f1 UP on r6 vs r0 (feature drop + fewshot doing work)
    - mean recall@p85/p90 UP on r6 (calibration improved)
    - test_auc roughly flat (ranking was already 0.92)

* If r6 doesn't beat r0 on test_best_f1, the v2 hypothesis is wrong; we
  pivot to a different intervention (BN adapters, MMD, label-only deploy
  calibration via isotonic). Don't iterate further on this branch.
