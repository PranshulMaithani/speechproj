RESULTING WORKBOOK  (6 sheets)
--------------------------------------------------------------------------------
  m1_default_last_pca98_casual_pred    per-file preds (mercer + casual rows)
  m1_default_last_pca98_casual_sweep   threshold sweep, all rows       (orig only)
  m1_default_last_pca98_casual_sweepT  threshold sweep, TEST + VAL rows (orig only)

Sheet 1 columns:
  Filename | real_id (blank for VLOOKUP) | GT (yes/no) | region (IND/PHP/CASUAL/UNK)
  | audios_folder (2/4/5/6/casual)
  | split_20%_test | Prediction_prob_20%_test
  | Prediction_prob_20%_test_noise | Prediction_prob_20%_test_pitch | ...    <-- per aug
  | split_a6_test  | Prediction_prob_a6_test
  | Prediction_prob_a6_test_noise  | Prediction_prob_a6_test_pitch  | ...    <-- per aug

  -> 'Prediction_prob_*' (no suffix) = prediction on the original (un-augmented) row.
  -> 'Prediction_prob_*_<aug>'       = prediction on the <aug>-augmented copy
                                        of the SAME row, scored through the same
                                        trained model. Use this to check whether
                                        train rows that score 0 FPs on orig are
                                        ALSO classified correctly under noise/
                                        pitch/etc. perturbation (generalisation
                                        within the aug neighbourhood) or only
                                        on the clean version (memorisation).

Sweep columns (_sweep, ALL rows):
  threshold | a6_fp a6_fn a6_tp a6_tn a6_precision a6_recall |
              split20_fp split20_fn split20_tp split20_tn
              split20_precision split20_recall
  (101 rows, threshold 0.00 -> 1.00 step 0.01; ORIG predictions only)

SweepT columns (_sweepT, TEST + VAL side by side, both protocols):
  threshold
  | a6_fp a6_fn a6_tp a6_tn a6_precision a6_recall                     <- a6 TEST
  | a6_val_fp a6_val_fn a6_val_tp a6_val_tn a6_val_precision a6_val_recall   <- a6 VAL
  | split20_fp ... split20_recall                                     <- 20% TEST
  | split20_val_fp ... split20_val_recall                             <- 20% VAL
  (101 rows; ORIG predictions only). Compare a6 vs a6_val (and split20 vs
  split20_val) at each threshold: if val and test confusion track each other,
  the chosen operating threshold generalises; if they diverge, the threshold
  is overfit to one split.

--------------------------------------------------------------------------------
"WHY IS THE TRAIN SET 0 FALSE PREDICTIONS?"  (overfitting check)
--------------------------------------------------------------------------------
What you saw: when filtering by split=train, FP=FN=0. Val/test look normal.

This is *expected* and not, by itself, evidence of harmful overfitting:

  1. With --use_augs all, the MLP trains on ORIG + 7 augmented copies of every
     train row = 8x the rows. The dump scores predictions on ORIG only -- the
     "easiest" copy. A 512->256->128 MLP on a ~600-dim PCA-reduced input has
     huge capacity to drive train BCE near zero on the clean version, while
     val F1 (the early-stop signal) gates real generalisation.

  2. Early stopping watches VAL F1, not train loss. The model is allowed to
     keep memorising train as long as val improves. If val plateaus and test
     still looks like train (=high F1 with non-trivial recall/precision), you
     have genuine learning, not memorisation.

  3. The harmful version of this (true overfitting) is: high train F1 + low
     val/test F1. You don't have that -- your val/test numbers were sensible.

The aug-prediction columns above are the DIRECT diagnostic for memorisation
vs. generalisation:

  - Pick a few train rows where ORIG is correct (FP=FN=0 region).
  - Look at Prediction_prob_*_noise / _pitch / _speed / _vtlp / _combo.
  - If those aug copies stay on the correct side of the threshold ==> the model
    has learnt features that survive perturbation = real generalisation.
  - If aug copies flip to the wrong side ==> it really did memorise clean
    features specific to those rows. THEN it's overfitting.

(One subtle point: augs were in the train set during fit, so the model has
literally SEEN those exact augmented rows. So train + aug = near-perfect is
also expected. The interesting diagnostic is whether VAL/TEST rows -- which
the model has NEVER seen in any aug form -- score consistently across all
their aug copies. Those are the true generalisation rows. Filter Sheet 1 by
split=val or split=test and look across the aug columns.)

NOTES

  aug-prediction overfitting check is unavailable).

--------------------------------------------------------------------------------
EXPORT + DOWNLOAD THE TRAINED MODELS  (--export_artifacts)
--------------------------------------------------------------------------------
Training does NOT save weights by default. To get downloadable models, add
  --export_artifacts true
to the SAME training commands (1-4 above). Re-run the full sweep (no --variants)
so the exported weights are the EXACT ones behind your finalised numbers.

It writes, into EVERY <out_dir>/<variant>/ :
  model.pt             MLP weights (state_dict, cpu tensors)
  scaler.joblib        the fitted StandardScaler (per WavLM layer)
  pca.joblib           the fitted PCA (omitted when pca=full)
  inference_meta.json  arch/hidden/dropout, wavlm_layer, pca, in_dim, feat_cols
                       (ordered), wavlm_id/whisper_id, target_sr, best_epoch,
                       best_f1_threshold, and the exact feature_order to rebuild
                       the input vector.

Your 2 models live at:
  Model 1: <m1 run>/default_last_pca98/{model.pt,scaler.joblib,pca.joblib,inference_meta.json}
  Model 2: <m2 run>/tiny_l9_pca95/{model.pt,scaler.joblib,pca.joblib,inference_meta.json}
(Model 1's reproducible run is the 20% OR a6 command depending which split you
want; the artifacts differ per split because train data differs.)
