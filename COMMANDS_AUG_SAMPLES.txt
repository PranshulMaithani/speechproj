================================================================================
A)  AUGMENTATION ABLATION   (ec2/aug_ablation.py)
================================================================================
Goal: for the 2 finalised models, attribute which of the 7 augs help/hurt --
WITHOUT the 2^7=128 subset grid (combinatorial + drowned in seed noise on small
candidate-wise test sets).

Models (hardcoded):
  Model 1: default / wavlm 'last' / pca98 / + casual (train-only)
  Model 2: tiny    / wavlm  l9    / pca95 / no casual
Splits: BOTH 20pct (60/20/20 candidate-wise) and a6 (test = all audios6).

Key design:
  * SPLIT IS FROZEN (single --split_seed): same candidates in train/val/test for
    every aug config + seed, so the aug set is the ONLY variable.
  * Only the TRAINING seed varies (MLP init / sampler / dropout). Averaging over
    --seeds separates a real aug effect from init luck. An aug "helps/hurts" only
    if |delta vs all| exceeds the seed std.
  * This is a SEPARATE experiment from the finalised runs -- it reseeds per run
    and does NOT reproduce the headline numbers bit-for-bit. That's expected.

Modes (--mode):
  loo     leave-one-out: 'all', 'drop_<aug>' x7, 'none'  (9 configs). Cleanest
          per-aug signal, lowest selection bias. (default)
  greedy  forward selection: start none, repeatedly add the aug that most
          improves mean VAL F1 (reports test). ~O(n^2) configs, finds a good
          subset + main interactions. Selection on val, NEVER test.
  both    run loo then greedy.

RUN (both modes, both splits, 5 seeds):
python ec2/aug_ablation.py \
    --data_dir /home/ubuntu/nn/data \
    --cache    /home/ubuntu/nn/data/embeddings_cache.npz \
    --out_dir  /home/ubuntu/nn/runs/aug_ablation \
    --seeds 42,43,44,45,46 \
    --mode both

(faster first look: --seeds 42,43,44  and/or --mode loo)

OUTPUTS (in --out_dir):
  aug_ablation_raw.csv      one row per (model, split, phase, aug_config, seed)
  aug_ablation_summary.csv  LOO: per (model,split,aug_config) mean/std test F1,
                            delta_test_best_f1 vs 'all', verdict
  aug_greedy_path.csv       greedy: step | chosen_aug | selected_set |
                            mean_val_f1 | mean_test_best_f1
  log_ablation.txt          full log (also prints the tables)

READING:
  LOO     'drop_X' with NEGATIVE delta => removing X hurt => X HELPS.
          POSITIVE delta => removing X helped => X HURTS.
          Trust only deltas whose |.| > the 'all' seed std (else '~neutral').
  greedy  last selected_set = recommended subset; its mean_test_best_f1 is the
          held-out estimate (selection was on val).

================================================================================
A2) ABLATION ANCHORED TO THE ORIGINAL MODELS   (ec2/aug_ablation2.py)
================================================================================
Why: aug_ablation.py 5-seed-averages EVERY config incl 'all', so its 'all' is a
FRESH estimate -- it does NOT reproduce the headline sheet (that was one run,
one training-luck draw). That is the 48->30 gap on M2/a6: same candidates,
different init luck.

aug_ablation2.py LOADS the original exported weights for each model x protocol
(model.pt + scaler.joblib + pca.joblib) and PREDICTS on the test rows -> the
'anchor_original' row is the EXACT headline number (M2/a6 recall@p90 = 0.48),
by real inference, not a CSV copy. It first PROVES the frozen split's test
candidates == the original predictions.csv group_ids, and that the
reconstructed pred_score == the saved pred_score (max|diff| < 1e-3). Then it
runs the same LOO + greedy ablation on that identical split.

Needs the 4 original runs with exported artifacts present:
  runs/m1_casual_a6/default_last_pca98/{model.pt,scaler.joblib,pca.joblib,...}
  runs/m1_casual_20pct/default_last_pca98/...
  runs/m2_nocasual_a6/tiny_l9_pca95/...
  runs/m2_nocasual_20pct/tiny_l9_pca95/...
(seed 42 + min_duration 30 were the original defaults -> split reproduces.)

RUN:
python ec2/aug_ablation2.py \
    --data_dir   /home/ubuntu/nn/data \
    --cache      /home/ubuntu/nn/data/embeddings_cache.npz \
    --out_dir    /home/ubuntu/nn/runs/aug_ablation2 \
    --runs_root  /home/ubuntu/nn/runs \
    --seeds 42,43,44,45,46 \
    --mode both
# override primary dir names if different:
#   --m1_a6_dir / --m1_20pct_dir / --m2_a6_dir / --m2_20pct_dir
# OPTIONAL no-aug anchor: if you ALSO have separately no-aug-trained, exported
# runs, pass them to load+predict an exact 'none' anchor too:
#   --m1_a6_none_dir <dir> --m1_20pct_none_dir <dir>
#   --m2_a6_none_dir <dir> --m2_20pct_none_dir <dir>
# (the anchor auto-reads each inference_meta.json: an all-aug run anchors 'all',
#  a no-aug run anchors 'none' -- the anchor_original sheet's orig_use_augs
#  column tells you what each finalised dir actually was.)

OUTPUTS (in --out_dir):
  aug_ablation2.xlsx               sheets: anchor_original | loo_summary_5seed |
                                   loo_summary_1seed | greedy_path | raw
  aug_ablation2_anchor.csv         EXACT original metrics (load+predict) per
                                   loaded model, with aug_kind (all/none),
                                   orig_use_augs, and verify cols:
                                   test_groups_match_orig (YES = same candidates),
                                   pred_max_abs_diff (<1e-3 = faithful repro)
  aug_ablation2_summary_5seed.csv  LOO mean/std over all 5 seeds + deltas
  aug_ablation2_summary_1seed.csv  LOO at seed 42 ONLY (single-draw replication,
                                   closest to how the headline number was made)
  aug_ablation2_raw.csv            per (model,split,aug_config,seed) fresh rows
  aug_greedy2_path.csv             greedy forward-selection path (5-seed val)

READING:
  * anchor_original  = the real headline numbers, reproduced by loading the
    original weights. If pred_max_abs_diff ~0 and test_groups_match_orig=YES,
    the load->predict path is exact.
  * 5-seed sheet = honest, init-luck-averaged aug effect.
    1-seed sheet = a single seed-42 training draw (this is the regime the
    original headline number lived in -- e.g. the M2/a6 48 vs 30 gap).
  * delta_test_best_f1 = vs the FRESH 'all' in that same sheet (clean aug
    effect). delta_*_vs_anchor = vs the ORIGINAL loaded model: 'all' configs vs
    the all-anchor, 'none' vs the none-anchor (if a no-aug run was provided).
  * If you did NOT pass --*_none_dir and your finalised runs are all-aug, there
    is no original 'none' weights to load -- 'none' stays the fresh floor and
    its delta_*_vs_anchor is NaN. To get an exact none anchor, train+export a
    no-aug run (neural_baseline_train ... --use_augs "" --export_artifacts true)
    and pass its dir via --*_none_dir.

================================================================================
A3) IN-SWEEP ABLATION THAT REPRODUCES THE HEADLINE NUMBER
    (ec2/neural_baseline_ablation.py -- a copy of neural_baseline_train.py)
================================================================================
Use this when you need the single-seed 'all' number to EXACTLY match your sheet
(e.g. M2/a6 recall@p90 = 0.48). aug_ablation2.py reseeds per config so it cannot
hit that number; this script runs the FULL original sweep so the RNG state at
the target variant is the exact headline state, then ablates from there.

How it works:
  * Runs the 30-variant sweep byte-identically (so every headline number repros).
  * When it reaches a --ablate_variants target, it snapshots the pre-train RNG,
    trains 'all' (== the sheet number) and each drop_<aug>/none from that SAME
    state, then restores the post-train RNG so later variants stay identical.
  * 'all' shares the headline init, so drop_<aug> deltas are a pure aug effect.

CRITICAL: run it with the SAME command/flags as that variant's ORIGINAL run, or
the RNG path differs and 'all' won't reproduce. The original flags are logged at
the top of runs/<orig_dir>/log_nn.txt. Just swap the script name, point --out_dir
somewhere new, and add --ablate_variants.

RUN (M2 on a6 -- mirrors the m2_nocasual_a6 command; keep --use_augs/--seed/
--train_only_batches/--test_batches/--min_duration EXACTLY as the original):
python ec2/neural_baseline_ablation.py \
    --data_dir /home/ubuntu/nn/data \
    --cache    /home/ubuntu/nn/data/embeddings_cache.npz \
    --out_dir  /home/ubuntu/nn/runs/m2_nocasual_a6_ablation \
    --test_batches audios6 \
    --min_duration 30 \
    --use_augs all \
    --ablate_variants tiny_l9_pca95
# M2 20pct: drop --test_batches.   M1 runs: use the m1_casual command (it adds
# casual via --train_only_batches) and --ablate_variants default_last_pca98.

OUTPUTS (in --out_dir):
  summary1.csv         the full 30-variant sweep (its tiny_l9_pca95 row should
                       equal your original m2_nocasual_a6 sheet row)
  ablation_sweep.csv   per (variant, aug_config): test_best_f1, recall@p80..95,
                       + delta_*_vs_all (vs that variant's own 'all' = headline)
  ablation_sweep.xlsx  sheets: ablation | sweep_summary

VERIFY: the ablation 'all' row == summary1.csv tiny_l9_pca95 == your sheet. If
yes, the drop_<aug>/none rows are trustworthy single-seed comparisons at the
exact operating point of the headline model.

================================================================================
B)  LISTEN TO THE AUGMENTATIONS   (2 scripts, npy -> wav only locally)
================================================================================
PII boundary:
  * Only .npy (numpy waveforms) + CODED ids (group_id) ever leave a machine.
  * NO .wav and NO real candidate ids are written on the EC2/packaging side.
  * wav files are created ONLY locally, by the second script.

DATA FLOW:
  [EC2 or laptop]  make_sample_package.py
        audio_npy/*.npy + gt.csv  -> apply 8 augs (exact training augmenters)
        -> aug_samples.zip   (npy + coded ids + manifest.csv)
   --(copy zip + your LOCAL cid_mapping.json to the listening machine)-->
  [listening machine]  make_listen_wavs.py
        -> npy -> wav, de-anonymize coded->real id
        -> samples/<batchtag>/<real_id>/<id>_q<qid>_<aug>.wav   (LOCAL ONLY)

--------------------------------------------------------------------------------
B1. PACKAGE (run where audio_npy/ lives -- EC2 or company laptop)
--------------------------------------------------------------------------------
python ec2/make_sample_package.py \
    --data_dir /home/ubuntu/nn/data \
    --out_zip  /home/ubuntu/nn/runs/aug_samples.zip

Defaults: 5 candidates/batch having ALL of Q25/26/27; audios6 split 5 IND + 5 PHP;
8 versions each (orig + noise,pitch,speed,gain,air,vtlp,combo).
  single-region batch -> 5 x 3 x 8 = 120 npy ;  audios6 -> 10 x 3 x 8 = 240 npy

Optional flags:
  --batches audios2,audios3,audios4,audios5,audios6   (add/remove batches)
  --region_split_batches audios6                      (which batches split by region)
  --per_batch 5            (candidates per batch / per region)
  --questions 25,26,27
  --augs orig,noise,pitch,speed,gain,air,vtlp,combo
  --seed 42               (deterministic candidate selection)

The zip contains: npy/<batch>__<group_id>__<region>__q<qid>__<aug>.npy + manifest.csv

--------------------------------------------------------------------------------
B2. BUILD WAVS (run LOCALLY, in the folder with the zip + cid_mapping.json)
--------------------------------------------------------------------------------
# deps:  pip install soundfile        (numpy already present)
python make_listen_wavs.py \
    --zip aug_samples.zip \
    --cid_mapping cid_mapping.json \
    --out_dir samples

  --keep_coded   name folders by coded group_id (skip de-anonymization)

OUTPUT TREE:
  samples/
    a2sample/<real_id>/<real_id>_q25_orig.wav
                       <real_id>_q25_noise.wav ... (8 augs)
                       <real_id>_q26_*.wav  <real_id>_q27_*.wav
    a4sample/...  a5sample/...
    a6sample_IND/<real_id>/...   a6sample_PHP/<real_id>/...
    manifest_real.csv      (local index incl. real ids -- do NOT upload)

batchtag rule: audios2->a2sample, audios3->a3sample, ... ; audios6 split by region.
Per candidate: 3 questions x 8 augs = 24 wav. Listen across the 8 augs of one
question to judge whether an augmentation is reasonable or destroys the speech.
